# Cypher query catalogue

Generated by scripts/gen_queries_doc.py — do not edit by hand.

Every query the product runs: 57 named, parameterised statements in `src/oncall_brain/adapters/falkordb/queries/*.cypher`. Code refers to them by name only (`repo.read("name", ...)` / `repo.write("name", ...)`); user input never becomes Cypher text. **RO** statements run through `GRAPH.RO_QUERY`, so the database itself rejects a write; **W** statements may write. Regenerate with `make docs`.

## ingest.cypher

**Ingest.** Loads the synthetic company: org, services, temporal dependencies, on-call shifts, changes, alerts, anomalies, past incidents and their sources. `services/seeding.py` runs them in order; each is `UNWIND $rows` + `MERGE` on a stable id, so re-seeding is idempotent.

### ingest_teams

**W** · `ingest.cypher` · used by `oncall_brain.services.seeding.seed` (write, via INGEST)

Upsert teams. Every ingest statement MERGEs on a stable id, so re-seeding is idempotent.

```cypher
UNWIND $rows AS r
MERGE (t:Team {id: r.id})
SET t.name = r.name
```

### ingest_people

**W** · `ingest.cypher` · used by `oncall_brain.services.seeding.seed` (write, via INGEST)

Upsert people (fake names) and their team membership.

```cypher
UNWIND $rows AS r
MERGE (p:Person {id: r.id})
SET p.name = r.name, p.handle = r.handle
WITH p, r
MATCH (t:Team {id: r.team})
MERGE (p)-[:MEMBER_OF]->(t)
```

### ingest_depends_on

**W** · `ingest.cypher` · used by `oncall_brain.services.seeding.seed` (write, via INGEST)

Upsert caller -> callee dependencies. valid_from / valid_to make the dependency map temporal.

```cypher
UNWIND $rows AS r
```


### ingest_incidents

**W** · `ingest.cypher` · used by `oncall_brain.services.seeding.seed` (write, via INGEST)

Upsert past, resolved incidents (episodic memory) with their cause, the runbook that fixed them and who was paged for the culprit service.

```cypher
UNWIND $rows AS r
MERGE (i:Incident {id: r.id})
SET i.title = r.title, i.symptom = r.symptom, i.status = r.status, i.opened_at = r.opened_at,
    i.resolved_at = r.resolved_at
WITH i, r
MATCH (s:Service {id: r.service}), (c:Change {id: r.cause}), (rb:Runbook {id: r.runbook})
MERGE (i)-[:IMPACTS {hops: 0}]->(s)
MERGE (i)-[:CAUSED_BY]->(c)
MERGE (i)-[:FIXED_WITH]->(rb)
WITH i, r
OPTIONAL MATCH (p:Person {id: r.paged})
FOREACH (x IN CASE WHEN p IS NULL THEN [] ELSE [p] END |
  MERGE (i)-[pg:PAGED]->(x)
  ON CREATE SET pg.at = r.opened_at, pg.for_service = r.paged_for)
```

## triage.cypher

**Triage.** Opens the incident board, walks `DEPENDS_ON` backwards for the blast radius, and finds who is on call at alert time from the rotation edges.

### open_incident

**W** · `triage.cypher` · used by `oncall_brain.services.tools.open_incident` (write)

Open the incident for an alert (idempotent). The incident is the shared board every agent reads and writes.

```cypher
MATCH (a:Alert {id: $alert_id})-[:FIRED_ON]->(s:Service)
MERGE (i:Incident {id: $incident_id})
ON CREATE SET i.status = 'open', i.opened_at = a.at, i.symptom = a.symptom, i.title = a.name
MERGE (i)-[:TRIGGERED_BY]->(a)
MERGE (i)-[:IMPACTS {hops: 0}]->(s)
RETURN i.id AS incident, i.status AS status, s.id AS service, a.at AS at, a.symptom AS symptom, a.name AS alert
```

### incident_head

**RO** · `triage.cypher` · used by `oncall_brain.services.tools._head` (read)

The incident's alerting service, alert time and status.

```cypher
MATCH (i:Incident {id: $incident_id})-[:TRIGGERED_BY]->(a:Alert)-[:FIRED_ON]->(o:Service)
RETURN i.id AS incident, i.status AS status, o.id AS service, a.id AS alert, a.at AS at, a.symptom AS symptom,
       a.name AS alert_name
```

### blast_radius

**RO** · `triage.cypher` · used by `oncall_brain.services.tools.blast_radius` (read)

Multi-hop impact: every service that transitively depends on $service via DEPENDS_ON edges valid at $at, with its shortest path.

```cypher
MATCH p = (caller:Service)-[:DEPENDS_ON*1..6]->(:Service {id: $service})
WHERE all(r IN relationships(p) WHERE r.valid_from <= $at AND (r.valid_to IS NULL OR r.valid_to > $at))
WITH caller, p
ORDER BY length(p)
WITH caller, collect(p)[0] AS p
MATCH (t:Team)-[:OWNS]->(caller)
RETURN caller.id AS service, caller.tier AS tier, length(p) AS hops, t.name AS team, [n IN nodes(p) | n.id] AS path
ORDER BY hops, service
```

### record_impacts

### storm_alerts

**RO** · `triage.cypher` · used by `oncall_brain.services.tools.correlate_alerts` (read)

Other alerts that fired in the $window seconds before this incident's alert (an alert storm).

```cypher
MATCH (i:Incident {id: $incident_id})-[:TRIGGERED_BY]->(a:Alert)
MATCH (other:Alert)-[:FIRED_ON]->(s:Service)
WHERE other.id <> a.id AND other.at >= a.at - $window AND other.at <= a.at
RETURN other.id AS alert, other.name AS name, s.id AS service, other.at AS at
ORDER BY at
```

### storm_upstream

**RO** · `triage.cypher` · used by `oncall_brain.services.tools.correlate_alerts` (read)

For each alerting service, every service it depends on at alert time (live edges, 0..6 hops) with the hop count, and whether that upstream service went red in the window. Related alerts share a red upstream; their common upstream is where one cause would sit.

```cypher
UNWIND $services AS sid
MATCH p = (:Service {id: sid})-[:DEPENDS_ON*0..6]->(u:Service)
WHERE all(r IN relationships(p) WHERE r.valid_from <= $at AND (r.valid_to IS NULL OR r.valid_to > $at))
WITH u, sid, min(length(p)) AS hops
RETURN u.id AS service, sid AS alerting, hops,
       size([(x:Anomaly)-[:ON]->(u) WHERE x.at >= $since AND x.at <= $at | x]) > 0 AS red
```

### record_correlation

**W** · `triage.cypher` · used by `oncall_brain.services.tools.correlate_alerts` (write)

Fold the related alerts into this incident (one incident, not one per alert), count their services as impacted, and mark the shared upstream ranked by convergence (fewest total hops from the alerting services).

```cypher
MATCH (i:Incident {id: $incident_id})
FOREACH (r IN $alerts |
  MERGE (other:Alert {id: r.alert})
  MERGE (i)-[:CORRELATED_WITH]->(other))
WITH i
UNWIND $alerts AS r
MATCH (s:Service {id: r.service})
MERGE (i)-[x:IMPACTS]->(s)
ON CREATE SET x.hops = 0, x.via = $origin
WITH DISTINCT i
UNWIND $shared AS u
MATCH (svc:Service {id: u.service})
MERGE (i)-[x:SHARED_UPSTREAM]->(svc)
SET x.rank = u.rank, x.hops = u.hops
RETURN count(svc) AS shared
```

## investigate.cypher

**Investigate.** Recalls similar past incidents by graph structure, turns changes on the live dependency path into hypotheses, and tests each one (live path, retired path, anomaly propagation), recording `SUPPORTS` / `REFUTES` evidence.

### recall_similar

**RO** · `investigate.cypher` · used by `oncall_brain.services.tools.recall_similar` (read)

Episodic recall by structure, not text: resolved incidents whose root-cause service is on the alerting service's live dependency path. Same symptom scores higher.

```cypher
MATCH (i:Incident {id: $incident_id})-[:TRIGGERED_BY]->(a:Alert)-[:FIRED_ON]->(o:Service)
MATCH (past:Incident {status: 'resolved'})-[:CAUSED_BY]->(c:Change)-[:CHANGED]->(cs:Service)
WHERE past.opened_at < a.at AND past.id <> i.id
MATCH p = (o)-[:DEPENDS_ON*0..6]->(cs)
WHERE all(r IN relationships(p) WHERE r.valid_from <= a.at AND (r.valid_to IS NULL OR r.valid_to > a.at))
WITH past, c, cs, a, min(length(p)) AS hops
OPTIONAL MATCH (past)-[:FIXED_WITH]->(rb:Runbook)
RETURN past.id AS incident, past.title AS title, past.symptom AS symptom, cs.id AS cause_service,
       c.kind AS cause_kind, c.id AS cause_change, hops, rb.id AS runbook, rb.title AS runbook_title,
       2 + CASE WHEN past.symptom = a.symptom THEN 1 ELSE 0 END AS score
ORDER BY score DESC, past.opened_at DESC
LIMIT 5
```

### memory_suspects

**RO** · `investigate.cypher` · used by `oncall_brain.services.tools.hypothesize_from_memory` (read)

Procedural memory decides: for each recalled incident, the runbook that fixed it names a service and a change kind; suspect in-window changes of that kind on that service, most trusted runbook first.

```cypher

WHERE x.score >= $min_score
MATCH (c:Change {kind: rb.kind})-[:CHANGED]->(cs)
```

### record_evidence

**W** · `investigate.cypher` · used by `oncall_brain.services.tools.check_hypothesis` (write)

Attach a check's verdict as an Evidence node (SUPPORTS / REFUTES the hypothesis) and update the hypothesis status.

```cypher
MATCH (h:Hypothesis {id: $hypothesis_id})
MERGE (e:Evidence {id: $evidence_id})
SET e.verdict = $verdict, e.reason = $reason, e.path = $path, e.at = $at, e.explains = $explains
WITH h, e, h.status AS before
// A human-confirmed cause stays confirmed whatever a later re-check says.
SET h.status = CASE WHEN h.status = 'confirmed' THEN h.status WHEN $verdict = 'supports' THEN 'supported'
                    WHEN $verdict = 'refutes' THEN 'refuted' ELSE 'inconclusive' END,
    h.coverage = $explains
FOREACH (_ IN CASE WHEN $verdict = 'supports' THEN [1] ELSE [] END | MERGE (e)-[:SUPPORTS]->(h))
FOREACH (_ IN CASE WHEN $verdict = 'refutes' THEN [1] ELSE [] END | MERGE (e)-[:REFUTES]->(h))
WITH h, before
// Procedural memory learns from misses too: a runbook whose suggestion was refuted loses confidence (once).
OPTIONAL MATCH (rb:Runbook {id: h.runbook})
FOREACH (x IN CASE WHEN rb IS NOT NULL AND $verdict = 'refutes' AND before = 'open' THEN [rb] ELSE [] END |
  SET x.uses = x.uses + 1)
RETURN h.id AS hypothesis, h.status AS status
```

### record_outranked

**W** · `investigate.cypher` · used by `oncall_brain.services.tools.conclude` (write)

When several suspects are supported, keep one leading cause and record why each other one lost (it explains fewer of the alerts, or sits further from the alert), as REFUTES evidence.

```cypher
UNWIND $rows AS r
MATCH (h:Hypothesis {id: r.id})
MERGE (e:Evidence {id: r.evidence_id})
SET e.verdict = 'outranked', e.reason = r.reason, e.at = $at
MERGE (e)-[:REFUTES]->(h)
SET h.status = 'outranked'
WITH e, h
// The same Evidence node supported this hypothesis a moment ago; it now only refutes it.
OPTIONAL MATCH (e)-[old:SUPPORTS]->(h)
DELETE old
RETURN count(DISTINCT h) AS outranked
```

## board.cypher

**Board.** The agents' shared state. The planner re-reads the board before every decision and every step is persisted as an `AgentStep`, so handoffs between roles happen through the graph.

### incident_board

**RO** · `board.cypher` · used by `oncall_brain.services.board.load_board` (read)

Everything the planner looks at, read fresh from the graph before every decision: steps already taken, hypotheses and their status, recalled memory.

```cypher
MATCH (i:Incident {id: $incident_id})-[:TRIGGERED_BY]->(a:Alert)-[:FIRED_ON]->(o:Service)
OPTIONAL MATCH (i)-[:LOGGED]->(st:AgentStep)
WITH i, a, o, collect({tool: st.tool, target: st.target, role: st.role}) AS steps
OPTIONAL MATCH (i)-[:HAS_HYPOTHESIS]->(h:Hypothesis)-[:SUSPECTS]->(c:Change)-[:CHANGED]->(s:Service)
WITH i, a, o, steps,
     collect({id: h.id, change_id: c.id, service: s.id, status: h.status, source: h.source, hops: h.hops,
              at: c.at, coverage: h.coverage}) AS hypotheses
OPTIONAL MATCH (i)-[x:RECALLS]->(past:Incident)
WITH i, a, o, steps, hypotheses,
     collect({incident: past.id, score: x.score, cause_service: x.cause_service}) AS recalls
OPTIONAL MATCH (other:Alert)
WHERE other.id <> a.id AND other.at >= a.at - $storm_window AND other.at <= a.at
WITH i, a, o, steps, hypotheses, recalls, count(other) AS storm
OPTIONAL MATCH (i)-[su:SHARED_UPSTREAM]->(u:Service)
WITH i, a, o, steps, hypotheses, recalls, storm, u, su
ORDER BY su.rank
RETURN i.id AS id, i.status AS status, o.id AS service, a.id AS alert, a.at AS at, a.symptom AS symptom,
       steps, hypotheses, recalls, storm, collect(u.id) AS shared_upstream
```

### update_facts

**RO** · `comms_memory.cypher` · used by `oncall_brain.services.tools.post_update` (read)

Facts for the status update: impact, who was paged and consulted, the supported cause with its author and sources (ticket, chat), and the runbook memory used.

```cypher
MATCH (i:Incident {id: $incident_id})-[:TRIGGERED_BY]->(a:Alert)
OPTIONAL MATCH (i)-[imp:IMPACTS]->(s0:Service)
WITH i, a, collect(DISTINCT {service: s0.id, via: imp.via}) AS impacts
OPTIONAL MATCH (i)-[:PAGED]->(p:Person)-[:MEMBER_OF]->(t:Team)
WITH i, a, impacts, collect(DISTINCT {name: p.name, handle: p.handle, team: t.name}) AS paged
OPTIONAL MATCH (i)-[cx:CONSULTED]->(x:Person)-[:MEMBER_OF]->(xt:Team)
WITH i, a, impacts, paged,
     collect(DISTINCT {id: x.id, name: x.name, handle: x.handle, team: xt.name, service: cx.for_service}) AS experts
OPTIONAL MATCH (i)-[:HAS_HYPOTHESIS]->(h:Hypothesis)-[:SUSPECTS]->(c:Change)-[:CHANGED]->(s:Service)

LIMIT 1
OPTIONAL MATCH (c)-[:AUTHORED_BY]->(author:Person)
OPTIONAL MATCH (src)-[:REQUESTED|MENTIONS]->(c)

OPTIONAL MATCH (rb:Runbook {id: h.runbook})
OPTIONAL MATCH (i)-[:FIXED_WITH]->(fx:Runbook)
WITH a, impacts, paged, experts, h, c, s, author, src, coalesce(rb, fx) AS rb
RETURN a.name AS alert, impacts, paged, experts, c.id AS change, c.summary AS change_summary,
       s.id AS cause_service, h.status AS cause_status,
       author.name AS author, collect(DISTINCT src.id) AS sources,

                         uses: rb.uses}) AS runbooks
```

Keep knowledge current: record a deploy or config change as it happens (idempotent on id).

```cypher
MATCH (s:Service {id: $service})
MERGE (c:Change {id: $id})
SET c.kind = $kind, c.summary = $summary, c.at = $at, c.rolled_back_at = $rolled_back_at
WITH s, c
// Re-recording an id corrects the change: drop its old service and author links first.
OPTIONAL MATCH (c)-[old:CHANGED|AUTHORED_BY]->()
DELETE old
WITH DISTINCT s, c
MERGE (c)-[:CHANGED]->(s)
WITH c
OPTIONAL MATCH (p:Person {id: $author})
FOREACH (x IN CASE WHEN p IS NULL THEN [] ELSE [p] END | MERGE (c)-[:AUTHORED_BY]->(x))
RETURN c.id AS change
```

### record_anomaly

**W** · `events.cypher` · used by `oncall_brain.services.tools.record_anomaly` (write)

Keep knowledge current: record a monitoring anomaly on a service.

```cypher
MATCH (s:Service {id: $service})
MERGE (x:Anomaly {id: $id})
SET x.kind = $kind, x.summary = $summary, x.at = $at
MERGE (x)-[:ON]->(s)
RETURN x.id AS anomaly
```

### raise_alert

**W** · `events.cypher` · used by `oncall_brain.services.tools.raise_alert` (write)

Record an alert on a service so the agents can respond to it.

```cypher
MATCH (s:Service {id: $service})
MERGE (a:Alert {id: $id})
SET a.name = $alert_name, a.symptom = $symptom, a.at = $at
MERGE (a)-[:FIRED_ON]->(s)
RETURN a.id AS alert
```

### add_dependency

**W** · `events.cypher` · used by `oncall_brain.services.tools.add_dependency` (write)

Keep knowledge current: caller starts depending on callee at $at (a new temporal DEPENDS_ON edge).

```cypher
MATCH (a:Service {id: $caller}), (b:Service {id: $callee})
OPTIONAL MATCH (a)-[live:DEPENDS_ON]->(b)
WHERE live.valid_to IS NULL
WITH a, b, collect(live) AS existing
// Only one live edge per pair: if the dependency already exists, keep it.
FOREACH (_ IN CASE WHEN size(existing) = 0 THEN [1] ELSE [] END |
  CREATE (a)-[:DEPENDS_ON {valid_from: $at}]->(b))
WITH a, b
MATCH (a)-[d:DEPENDS_ON]->(b)
WHERE d.valid_to IS NULL
RETURN a.id AS caller, b.id AS callee, d.valid_from AS valid_from
```

### retire_dependency

**W** · `events.cypher` · used by `oncall_brain.services.tools.retire_dependency` (write)

Keep knowledge current: close the live caller -> callee dependency at $at (history is kept; queries at later times stop using it).

```cypher
MATCH (:Service {id: $caller})-[d:DEPENDS_ON]->(:Service {id: $callee})
WHERE d.valid_to IS NULL AND d.valid_from <= $at
SET d.valid_to = $at
RETURN count(d) AS retired
```
