# Deploying On-call Brain

One container serves everything: the web UI and HTTP API at `/`, the MCP server (Streamable HTTP) at `/mcp` and
`/health` (`src/oncall_brain/serve.py`, what the `Dockerfile` runs). All state lives in FalkorDB, one graph per tenant,
so the container is stateless; FalkorDB comes from FalkorDB Cloud (`FALKORDB_URL`) or from docker-compose.

## A. FalkorDB Cloud + Render: the checklist (free tiers, about 15 minutes, only sign-ins and pasting)

1. **GitHub.** Push this repository to a GitHub repository you own. Render deploys from it.
2. **FalkorDB Cloud.** Sign in at https://app.falkordb.cloud, create a free database, open its connection details and
   build one URL from them: `rediss://<username>:<password>@<host>:<port>` (`redis://` if the instance has no TLS).
   Keep it for step 3. Optional check from your machine: `FALKORDB_URL='rediss://...' make demo` must end with
   `DEMO OK` (a Cloud instance may run another FalkorDB version than the v4.22.0 pinned locally; if a query fails,
   note which).
3. **Render.** Sign in at https://dashboard.render.com, New > Blueprint, pick the repository. `render.yaml` creates one
   Docker web service, `oncall-brain`, on the free plan with its health check on `/health`. The blueprint asks for
   `FALKORDB_URL`: paste the URL from step 2. `MCP_TOKEN` is generated by Render. `ALLOWED_HOSTS` stays empty: the
   app accepts the hostname Render sets (`RENDER_EXTERNAL_HOSTNAME`). Apply, then wait for the first deploy: the
   image builds, seeds the demo company once (`python -m scripts.seed --if-missing`, so restarts keep learned
   runbooks), and listens on Render's `$PORT`.
4. **Check.** Open `https://<service>.onrender.com/health`: `"ok": true`, `"falkordb": true`, `"mcp": "/mcp"`. Open
   `https://<service>.onrender.com/` for the UI: 0 Reset, then 1 Act 1.
5. **Token.** In the service's Environment tab, copy the value of `MCP_TOKEN`.
6. **Claude Code, from anywhere.** With the plugin (`claude --plugin-dir ./plugin` from a checkout, or
   `/plugin install oncall-brain --marketplace <owner>/<repo>`), and nothing else installed:
   ```bash
   export ONCALL_BRAIN_URL=https://<service>.onrender.com
   export ONCALL_BRAIN_TOKEN=<the MCP_TOKEN value>
   claude --plugin-dir ./plugin mcp list        # plugin:oncall-brain:oncall-brain-remote ... Connected
   ```
   Then `/oncall-brain:incident alert:checkout-latency` and `/oncall-brain:who-owns kafka` in a session. Any other
   MCP client uses the same URL with `Authorization: Bearer <token>` (see [MCP.md](MCP.md)).
7. **Optional: an LLM planner and Slack.** In the Environment tab add `LLM_PROVIDER=anthropic` and
   `ANTHROPIC_API_KEY=<key>` (or `LLM_API_KEY`); without them the deterministic planner runs. `SLACK_WEBHOOK_URL`
   posts every status update to a channel.

Free Render instances sleep when idle; the first request after a while takes about 30 s. Record the demo video
against a warm instance.

## B. Any VM with Docker

```bash
MCP_TOKEN=<choose one> docker compose up --build -d   # falkordb/falkordb:v4.22.0 + the app on 127.0.0.1:8000: UI, API, /mcp, /health
docker compose --profile mcp up --build -d            # plus the standalone MCP server, no token, on 127.0.0.1:8001/mcp
```
Ports are published on 127.0.0.1 only. Put a reverse proxy (Caddy, nginx) with TLS in front of port 8000, pass the
`Host` header through, and add the public name to `ALLOWED_HOSTS`. Do not publish 6379: FalkorDB in the compose file
has no password.

## C. A static replay on GitHub Pages (no backend)

`.github/workflows/pages.yml` publishes `web/` on every push to main (enable once: Settings -> Pages -> Source: GitHub
Actions). With no API behind it, the UI notices and replays the recorded runs in `web/fixtures/` (regenerate them with
`python -m scripts.gen_fixtures` after changing the agents; act 2's recording includes the same-incident memory
comparison). The header then shows a "recorded replay" chip instead of a FalkorDB connection chip. Everything except
the Ask tab (it lists example questions instead) and live resets works. `.github/workflows/ci.yml` runs lint, the
query-doc check, the demo and the tests against `falkordb/falkordb:v4.22.0` on every push.

## Settings that matter in public

| Setting | Why |
|---|---|
| `MCP_TOKEN` | Required by `/mcp` on a deployment: without it that endpoint answers 401 (the UI and API still work). The plugin sends it as `ONCALL_BRAIN_TOKEN`. |
| `API_TOKEN` | If set, every `/api/*` call except `/api/health` needs `Authorization: Bearer <token>`, and it doubles as the MCP token when `MCP_TOKEN` is empty. The bundled UI does not send it, so set this only for API/MCP-only deployments. Without it, anyone who can reach the URL can drive the demo company (simulate, confirm, reset, every write tool) through the UI's API; the MCP token guards `/mcp` only. |
| `ALLOWED_HOSTS` | Host-header allow-list (blocks DNS rebinding) on the API and the MCP endpoint. The hostname Render (`RENDER_EXTERNAL_HOSTNAME`) or Railway (`RAILWAY_PUBLIC_DOMAIN`) sets is accepted by itself; list any other public name here. |
| `MAX_TENANTS` | Each new tenant costs two graphs; resetting a new tenant past the cap returns 429. |
| `FALKORDB_URL` / `FALKORDB_SSL` | Connection to a hosted FalkorDB (TLS). |

`/health` answers on any `Host` (a platform's checker may not send the public name) and reveals only flags. There is
no per-user auth: anyone with the token can address any tenant over MCP, and anyone who can reach the API can address
any tenant there. That is fine for a demo; a real deployment would put an identity-aware proxy in front and map users
to tenants.

## MCP for remote clients

A deployment serves MCP at `https://<host>/mcp` with the bearer token above, from the same process as the UI and API;
[MCP.md](MCP.md) lists the clients (Claude Code's plugin remote mode, `claude mcp add --transport http`, the Inspector,
any MCP SDK). The standalone server, `python -m oncall_brain.mcp_server --http --host 0.0.0.0 --port 8001`, still
runs as a second process next to `make dev`; it checks `Host` and `Origin` the same way and needs no token unless one
is set. `tests/integration/test_deploy.py` starts the deployment app as the Dockerfile does and checks all of this from
outside: `/health`, the open API, the UI, the Host checks on both halves, 28 tools and an `ask` over `/mcp`, 401 on a
wrong token.
